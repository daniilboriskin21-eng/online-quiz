# Онлайн-квиз для друзей

Fullstack-приложение для проведения викторин в реальном времени. Ведущий создаёт комнату с готовым квизом, друзья подключаются со смартфонов или компьютеров по 6-значному коду, отвечают на вопросы с ограничением времени, а сервер ведёт подсчёт очков и объявляет победителей на пьедестале.

Проект разработан на чистом JavaScript: **React + Vite** на клиенте, **Node.js + Express + Socket.IO** на сервере, **PostgreSQL** в качестве базы данных.

---

## Архитектура и ключевые особенности

- **Авторитетный сервер (Server Authority):** таймер раунда и дедлайн (`ends_at`) рассчитываются и проверяются исключительно на сервере. Клиентские таймеры служат только для плавной анимации.
- **Защита от читерства (Data Hiding):** правильный вариант ответа принципиально скрыт на сервере и не отправляется в сеть до момента официального закрытия раунда.
- **Идемпотентность и целостность:** повторные клики или повторные пакеты при нестабильной сети подтверждают уже сохранённый ответ без дублирования очков. Ограничения `UNIQUE` в PostgreSQL исключают гонки данных.
- **Отслеживание присутствия (Presence):** статус игроков (`🟢 в сети` / `⚪ не в сети`) динамически обновляется через Socket.IO в оперативной памяти сервера, не удаляя участников из базы данных при перезагрузке страницы.
- **Восстановление после сбоев (Crash Recovery):** при перезагрузке вкладки (F5) участник возвращается в активный раунд с сохранённым ответом и временем. При рестарте сервера Node.js активные раунды автоматически восстанавливаются или закрываются по истечении срока.
- **Адаптивность:** интерфейс оптимизирован как для десктопов, так и для мобильных устройств.

- `client/` — React + Vite, интерфейс викторины, сокет-клиент.

## Быстрый старт

### 1. Настройка переменных окружения

В корне проекта скопируйте пример файла конфигурации:
```powershell
Copy-Item server/.env.example server/.env
```

Заполните параметры подключения к вашей базе данных PostgreSQL в файле `server/.env`:
```env
PORT=3000
PGHOST=localhost
PGPORT=5432
PGDATABASE=online_quiz
PGUSER=quiz_app
PGPASSWORD=ваш_пароль
```

### 2. Подготовка базы данных PostgreSQL

Под администратором PostgreSQL создайте пользователя и базу:
```sql
CREATE ROLE quiz_app WITH LOGIN;
\password quiz_app
CREATE DATABASE online_quiz OWNER quiz_app;
```

Подключитесь к базе `online_quiz` под пользователем `quiz_app` и выполните по порядку все миграции:
```powershell
psql -U quiz_app -d online_quiz
```

В консоли `psql`:
```text
\set ON_ERROR_STOP on
BEGIN;
\i server/sql/001_create_quizzes.sql
\i server/sql/002_seed_quizzes.sql
\i server/sql/003_create_questions.sql
\i server/sql/004_seed_questions.sql
\i server/sql/005_create_options.sql
\i server/sql/006_seed_options.sql
\i server/sql/007_seed_options_second_question.sql
\i server/sql/008_create_rooms.sql
\i server/sql/009_add_room_status.sql
\i server/sql/010_create_members.sql
\i server/sql/011_create_rounds.sql
\i server/sql/012_create_answers.sql
COMMIT;
```

Проверить подключение можно проверочным скриптом:
```powershell
cd server
node --env-file=.env check-db.js
```

### 3. Установка зависимостей

В корне репозитория:
```powershell
cd client
npm install
cd ../server
npm install
cd ..
```

### 4. Запуск в режиме разработки

Откройте два окна терминала.

**Терминал 1 (Сервер):**
```powershell
cd server
npm run dev
```
*(Сервер запустится на `http://localhost:3000` в режиме `--watch`)*.

**Терминал 2 (Клиент):**
```powershell
cd client
npm run dev
```
*(Клиент откроется на `http://localhost:5173`)*.

## Игровой процесс

1. **Создание комнаты:** Ведущий выбирает квиз и нажимает «Создать комнату». Сервер генерирует уникальный 6-значный код комнаты и выдаёт ведущему сессионную cookie `quiz_session`.
2. **Вход игроков:** Игроки вводят код комнаты и свой никнейм. Состав лобби обновляется в реальном времени.
3. **Старт игры:** Ведущий нажимает «Начать игру» (кнопка активна, если есть хотя бы 1 игрок).
4. **Раунд вопроса:** Все участники видят вопрос, 4 варианта ответа и синхронный 30-секундный таймер. После клика ответ игрока фиксируется сервером и кнопки блокируются.
5. **Итоги раунда:** По истечении времени раунд автоматически закрывается, подсвечивается правильный ответ и выводится промежуточная таблица лидеров с очками и местами (спортивное ранжирование 1, 1, 3...).
6. **Следующий вопрос / Финал:** Ведущий нажимает «Следующий вопрос →». Когда вопросы квиза исчерпаны, кнопка меняется на «Показать итоги игры 🏆».
7. **Пьедестал и выход:** Открывается экран финала с медалями 🥇🥈🥉. Кнопка «Выйти в главное меню» корректно отзывает сессию в базе данных и очищает cookie.

## Контракт обмена данными

### HTTP API

| Метод & Маршрут | Описание | Доступ |
|---|---|---|
| `GET /api/health` | Проверка жизнеспособности сервера | Публичный |
| `GET /api/quizzes` | Список доступных квизов и число вопросов | Публичный |
| `POST /api/rooms` | Создание комнаты ведущим | Публичный |
| `POST /api/rooms/:code/join` | Вход игрока по коду комнаты и никнейму | Только в `lobby` |
| `GET /api/session` | Восстановление текущей сессии пользователя | По cookie |
| `GET /api/rooms/:code` | Получение информации о комнате | Участникам |
| `POST /api/session/leave` | Отзыв сессии и выход из игры | Участникам |

### Socket.IO события

- **Клиент → Сервер:**
  - `game:start` — запуск игры ведущим из лобби.
  - `answer:submit` — отправка ответа игроком `{ roundId, optionId }`.
  - `game:continue` — переход к следующему вопросу или к финалу.
- **Сервер → Клиент:**
  - `room:state` — полное персональное состояние комнаты (`room`, `me`, `players`, `round`, `myAnswer`, `results`).
