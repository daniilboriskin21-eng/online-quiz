# Онлайн-квиз для друзей

Учебный fullstack-проект на JavaScript. Планируется игра, в которой ведущий создаёт комнату, друзья подключаются по коду и отвечают на вопросы.

Реализованы React-клиент, Express-сервер, PostgreSQL и загрузка списка квизов с количеством вопросов. В базе есть тестовый квиз из двух вопросов с четырьмя вариантами и одним правильным ответом у каждого. Интерфейс показывает загрузку, ошибку и пустой список. Комнаты, игровой процесс и Socket.IO пока не реализованы.

## Структура

- `client/` — React + Vite, интерфейс приложения.
- `server/` — Node.js + Express, HTTP API.

У каждого приложения свой `package.json` и свой набор зависимостей. Команды npm выполняются внутри соответствующей папки.

## Окружение

Проект проверялся в Windows PowerShell с Node.js `24.17.0` и npm `11.13.0`. Для воспроизведения окружения можно использовать эти версии.

Проверить установленные версии:

```powershell
node --version
npm.cmd --version
```

Ниже используется `npm.cmd` для PowerShell в Windows. В других оболочках можно использовать `npm`.

Для списка квизов нужен PostgreSQL (проверена версия 17.4). Порт Express и параметры подключения к базе задаются в `server/.env`. Перед первым запуском создай этот локальный файл из примера, выполнив из корня репозитория:

```powershell
Copy-Item server/.env.example server/.env
```

Команда копирует пример настроек. Выполняй её, только если `server/.env` ещё не существует, чтобы не перезаписать свои значения. В примере указано `PORT=3000`. Файл `.env` исключён из Git; `.env.example` хранится в репозитории без секретов.

Node.js загружает файл через `--env-file=.env`; для команд запуска этот файл обязателен. Если внутри файла нет `PORT`, код использует `3000`. После изменения `.env` перезапусти сервер вручную. Если меняешь порт, также обнови адрес назначения `/api` в `client/vite.config.js` и перезапусти Vite.

Заполни `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` и `PGPASSWORD`. Пример рассчитан на `localhost:5432`, базу `online_quiz` и роль `quiz_app`; пароль задаётся только в локальном `.env`.

## Подготовка PostgreSQL

Следующие действия предназначены для новой базы. Существующую рабочую базу повторно инициализировать не нужно. SQL-файлы выполняются один раз по порядку: повторная загрузка данных может создать дубликаты или завершиться ошибкой ограничения.

В PowerShell переключи кодировку перед запуском `psql`:

```powershell
chcp 65001
$env:PGCLIENTENCODING = "UTF8"
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h localhost -p 5432 -U postgres -d postgres
```

Если PostgreSQL установлен в другом месте, исправь путь. Под административной ролью создай роль приложения и базу (если их ещё нет):

```sql
CREATE ROLE quiz_app WITH LOGIN;
```

```text
\password quiz_app
```

Команда запросит пароль без отображения ввода. Сохрани его в `PGPASSWORD` своего `.env`.

```sql
CREATE DATABASE online_quiz OWNER quiz_app;
```

Выйди через `\q`. Открой PowerShell в корне репозитория и подключись как пользователь приложения:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h localhost -p 5432 -U quiz_app -d online_quiz
```

В `psql` выполни файлы в одной транзакции. `ON_ERROR_STOP` останавливает выполнение файла при ошибке. Если любая команда завершилась ошибкой, выполни `ROLLBACK;` и разберись с причиной вместо продолжения.

```text
\set ON_ERROR_STOP on
BEGIN;
\i server/sql/001_create_quizzes.sql
\i server/sql/002_seed_quizzes.sql
\i server/sql/003_create_questions.sql
\i server/sql/004_seed_questions.sql
\i server/sql/005_create_options.sql
\i server/sql/006_seed_options.sql
\i server/sql/007_seed_options_second_question.sql
```

Перед сохранением проверь комплектность:

```sql
SELECT q.position AS question_number,
       count(o.id) AS option_count,
       count(o.id) FILTER (WHERE o.is_correct) AS correct_count
FROM questions q
LEFT JOIN options o ON o.question_id = q.id
WHERE q.quiz_id = (SELECT id FROM quizzes WHERE title = 'Кино')
GROUP BY q.id, q.position
ORDER BY q.position;
```

Ожидаются два вопроса, у каждого `option_count = 4` и `correct_count = 1`. Если результат совпал, выполни `COMMIT;`, иначе — `ROLLBACK;`. Четыре варианта и ровно один правильный проверяются этим запросом; схема сама по себе не гарантирует полноту набора. Автоматические ID могут отличаться от примеров и иметь пропуски.

После установки зависимостей проверь подключение из папки `server`:

```powershell
node --env-file=.env check-db.js
```

Ожидаются база `online_quiz` и пользователь `quiz_app`. Проверочный скрипт закрывает пул после запроса.

## Установка зависимостей

Открой терминал в корне репозитория и выполни:

```powershell
cd client
npm.cmd install
cd ../server
npm.cmd install
cd ..
```

`npm.cmd install` устанавливает зависимости приложения в его папку `node_modules`. Повторять установку перед каждым запуском не требуется.

Файлы `package.json` и `package-lock.json` хранятся в Git; `node_modules` исключён из Git.

## Запуск для разработки

Нужны два терминала, изначально открытых в корне репозитория.

В первом запусти сервер:

```powershell
cd server
npm.cmd run dev
```

При `PORT=3000` Express слушает `http://localhost:3000`. Команда запускает `node --env-file=.env --watch index.js`: загружает настройки и автоматически перезапускает процесс при изменении серверных файлов.

Во втором запусти клиент:

```powershell
cd client
npm.cmd run dev
```

Открой адрес из строки `Local` в выводе Vite, обычно `http://localhost:5173`. Если порт занят, Vite может выбрать другой — используй адрес из терминала.

Оба терминала должны оставаться работающими. Для остановки приложения нажми `Ctrl+C` в его терминале.

## Проверка связи

1. При работающих клиенте и сервере открой страницу клиента.
2. Нажми «Проверить сервер». Ожидаемое сообщение: `Статус сервера: ok`.
3. Останови только Express через `Ctrl+C`, оставив Vite работающим.
4. Нажми кнопку снова. Ожидаемое сообщение: `Не удалось связаться с сервером`.
5. Снова запусти Express командой `npm.cmd run dev` из папки `server` и повтори проверку.

Маршрут `GET /api/health` возвращает:

```json
{"status":"ok"}
```

Его можно открыть напрямую по адресу `http://localhost:3000/api/health` или через адрес Vite с путём `/api/health`.

React отправляет запрос на относительный адрес `/api/health`. Прокси в `client/vite.config.js` передаёт запросы `/api` в Express на `http://localhost:3000`, сохраняя путь. Эта настройка относится к серверу разработки Vite; размещение приложения ещё не настроено.

## Проверка списка квизов

При работающих PostgreSQL, Express и Vite нажми «Загрузить квизы». Ожидается «Кино — вопросов: 2». Повторное нажатие запрашивает актуальные данные из базы. Во время запроса кнопка заблокирована, показано «Загружаем…». После ошибки доступна повторная попытка, при пустом массиве — сообщение «Пока нет доступных квизов».

`GET /api/quizzes` возвращает `{ "data": [{ "id": 3, "title": "Кино", "questionCount": 2 }] }` (ID зависит от базы). Ответ не содержит текстов вопросов, вариантов или признаков правильности. `/api/health` проверяет доступность Express, а не соединение с PostgreSQL.

## Другие команды

Из папки `client`:

```powershell
npm.cmd run lint
npm.cmd run build
```

`lint` проверяет код с помощью ESLint. `build` собирает клиент в `client/dist`. Сборка сама по себе не запускает Express и не заменяет проверку приложения в браузере.

Из папки `server`:

```powershell
npm.cmd start
```

Загружает `.env` и запускает Express без автоматического перезапуска при изменении файлов. Не запускай одновременно с уже работающим сервером на том же порту.
